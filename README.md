# Social Dual Post

将与 AI 的对话整理成独立选题，生成朋友圈文案和抖音逐页图文稿，并在用户反馈中逐步调整表达。

当前版本：**0.3.0**。这是可在 Codex 中使用的文件型 Skill，不是独立运行的应用或自动发布服务。

## 使用

将仓库目录完整复制到 `~/.codex/skills/social-dual-post/`，在下一轮对话中调用：

```text
用 $social-dual-post 梳理本次对话，提炼值得表达的主题，
生成朋友圈和抖音图文稿，修订后给我审核。
```

其他用法：

- “只提取选题，先不写正文。”
- “只写第一个主题的朋友圈，不保存。”
- “这个开头太平，抓住主要矛盾改一下，记下这次意见。”
- “以后朋友圈默认先说问题，把这个设为偏好。”

只处理当前可见对话和明确提供的素材；在另一个聊天使用时，需要提供对应文本或文件。当前不要求 API Key 或第三方 Python 包。实际模型能力和工具权限由运行环境提供。

## 流程

提取观点 → 选题评审 → 确定主线与结构 → 分平台写作 → 有限修订 → 用户审核 → 反馈留存。

- 默认最多选择两个独立主题，每题生成朋友圈与抖音稿；用户可指定范围。
- 抖音交付逐页文字和画面建议，不默认生成图片或发布内容。
- 不要求固定人设，不编造个人经历，不把 AI 建议当作用户立场。
- 模型自评分仅是编辑建议，不证明内容质量或传播效果。

## 反馈与个人数据

反馈默认存放在使用项目的 `output/social-posts/_learning/`，可指定其他目录。局部修改保留为案例，用户明确确认后才成为相应范围的长期偏好。普通写稿不会自动重写 Skill 核心规则或写入 Codex 全局记忆。

文章、真实聊天、反馈、偏好和凭证均不属于此仓库的发布内容。默认项目学习目录会创建 `.gitignore`；这不能替代对已跟踪文件和 Git 历史的检查。

## 验证范围与维护

当前做过 Skill 格式校验和隔离场景试跑，包含多主题、单平台、不保存、局部反馈、确认偏好及新上下文读取偏好。`tests/scenarios.md` 是可重复执行的人工／模型评测场景，不是已建成的自动化测试套件。

维护源以本仓库为准；安装目录为使用副本。修改后先用实际场景验证，再同步安装目录。版本变化见 [CHANGELOG.md](CHANGELOG.md)。
