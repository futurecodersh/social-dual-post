# 选题与成稿评审

评分是模型的编辑判断，不能当客观认证、平台算法指标或流量预测。不要模拟多个名人评委来制造独立共识。不计算加权总分，不让文笔分掩盖事实问题。每项用 1–5 整数并给具体依据；证据不足写“待判断”，不用中间分掩饰未知。

完整分维评审保存在本次 review.md 中，无法保存时在内部完成。对外默认只给简短选题理由、一句编辑结论与至多两个重要问题，不让评分报告压过文章；用户要求评分、评测或完整评审时再展示分数与依据。短篇单平台内容也遵守此展示规则，不强制附两张评分表。

## 共用标尺

1 = 明显不成立或偏离；2 = 存在影响表达的缺口；3 = 成立、可读但普通；4 = 明确有价值且有素材支撑；5 = 有鲜明洞察、支撑充分、表达贴切。5 分不是每次的目标，也不意味着必然获得传播。不同维度按其问题具体解释，不靠分数代替判断。

## 写作前：选择值得表达的题目

候选清单每行包含：ID、核心问题／视角、素材定位、价值／真实／平台／吸引力四项评分、建议与主要依据。平台适配分别注明朋友圈和抖音，不把“适合朋友圈”直接推为“适合抖音”。清单应短，避免写成长篇策略报告。

| 维度 | 判断问题 |
|---|---|
| 内容价值 | 留下了什么值得重看或讨论的观察、疑问或判断？对读者是否有具体帮助或共鸣？不要求每篇都有新理论、数据或教程。单纯宣告“我要输出”不自动具有高价值。 |
| 个人真实性 | 用户是否确有这个观察或疑问？有什么具体经历、原话和判断可支撑？探索中的问题可以成立，不要求成功案例。若用户明确形象偏好则检查一致性，否则只判断忠实与辨识度，不猜人设。 |
| 平台适配 | 熟人阅读是否自然？抖音是否能拆成逐页递进，且陌生读者不用看原聊天也能理解？题材、隐私或篇幅是否让某平台不合适？ |
| 视角吸引力 | 是否有一个清楚的问题、真实张力或读者容易忽略的区分？无需靠制造焦虑、假反常识和夸张标题。 |

建议有四类：优先写（素材与角度都清楚）、可写（价值成立但普通或适用读者窄）、补素材（关键部分无法支持）、暂存（目前不值得展开或与本次重复）。评审不要求固定人设，个人能力可以通过问准问题、讲清权衡、修正判断自然体现。

## 写作后：先检查阻断问题，再给编辑分

阻断问题包括：伪造用户经历或身份；核心事实或数字无依据；AI 建议冒充用户立场；不可公开隐私；标题承诺正文无法兑现。修正、删去该主张或标记待补后再交付，不用免责声明替代修正。

按题目与平台分别评审，简短列出：

| 维度 | 判据 |
|---|---|
| 内容价值兑现 | 正文是否真正解释了选题承诺，而不只剩感慨与漂亮句子？ |
| 个人表达 | 是否忠实于素材、保留用户的阶段和语气？编辑分析是否被误写成亲历认知？ |
| 平台适配 | 朋友圈是否自然有余味；抖音是否陌生读者可懂、每页增加信息、上图文字可用？ |
| 结构吸引力 | 开头是否给出继续读的理由，中间是否递进、有例子或机制，结尾是否有所落点？ |
| 语言质感 | 凝练准确、节奏变化、可理解的文学感，有无术语堆砌、强行升华、重复口号？ |

每篇指出至多两个最影响效果的问题及已经做的修改，必要时说明未解决项；并非为显示评审存在而捏造缺点。编辑结论用“可供审核／已修订可供审核／待补素材”，不要写“用户已通过”。用户审核后按实际意见继续改，单次修改不自动变成所有文章的永久规则。

复审增加三项实际检查：前两段是否呈现读者关心的问题；全文能否用一句话概括同一主线；历史、数字和术语是否压过了这条主线。评分必须关联具体句段或页码；不能因为格式完整就给结构、平台和语言全部默认 4 分。各项相同可以成立，但每项都要独立给理由。只评用户请求的平台。用户反馈表明首次评审漏掉问题时，把差异记入本次 review，不能追溯改写旧评分来制造“早已发现”的假象。长期偏好的更新按 feedback.md 执行。

## 方法借鉴与差异

本文件按当前用户需求独立编写，未复制第三方规则文本：

- Creator Stack 的 [extract-ideas](https://github.com/kenneth-liao/ai-launchpad-marketplace/blob/main/creator-stack/skills/extract-ideas/SKILL.md)：借鉴观点关联原始素材、单题单核心、质量不足不凑数的思路。这里不沿用作者人设、海外平台或强制子代理流程。
- WeWrite 的 [内容质量验收](https://github.com/imraywang/wewrite/blob/main/docs/content-quality-rubric.md)：借鉴内容价值、作者表达、事实边界及实际修订再复审的思路。这里不采用公众号优先、热点优先或统一平均分门槛。

这些链接用于维护者追溯参考，不代表已经验证其运行效果；使用本 Skill 不要求安装这些项目，也无需每次写稿联网读取。
