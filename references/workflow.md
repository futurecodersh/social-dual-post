# 执行流程与产物

输入是当前可见讨论或用户指定素材，不假定能取得别的聊天。先判断是新写作、只选题，还是已有稿件的审核反馈；后者直接进入反馈处理，不重跑整条生产流程。

| 步骤 | 输入 | 本步产物 | 转移条件 |
|---|---|---|---|
| 1 提取 | 对话及当前指令 | 主题、核心疑问／判断、短原话定位、归属及不确定性 | 每题可溯源，纠正后的立场已保留；不相关话题分开。同义合并，不先摘要丢细节。 |
| 2 选题 | 主题清单 | 推荐顺序、价值与平台理由、入选题 | 按 review.md 评审。默认最多两题，允许一题，不凑数；其余留清单。用户只要选题则在此交付。没有可写题则问一个关键问题。 |
| 3 构思 | 入选题、证据、已确认偏好 | 每题一行主线、一种合适的结构、必要支撑 | 能说明读者为什么关心；无关资料移出。疑问可成立，不强迫定论；不拿一个观点的多个同义角度凑篇。 |
| 4 写作 | 主线及平台要求 | 每题对应平台的完整稿件 | 遵循 SKILL.md。用户只要一个平台则只写该平台；某平台明显不适配则解释暂缺。 |
| 5 复审修订 | 稿件、原始素材、已确认偏好 | 修订稿、具体缺陷及处理记录 | 按 review.md 先核事实再查主线、开头和信息负担。默认最多两轮，不追逐高分。仍缺关键材料则标待补，不伪称通过。 |
| 6 交付 | 最终可用稿件 | 清单、成稿、精简评审、路径、待用户审核状态 | 写盘后回读。模型可供审核不等于用户已批准，绝不自动发布。 |
| 7 反馈 | 用户评语与对应版本 | 局部修订、反馈记录、可选偏好提议 | 读 feedback.md；用户只评价而未要求修改时不擅自重写。学习只做本次一轮，不递归修改通用 Skill。 |

默认内部完成构思及至多两轮修订，不要求用户逐步批准。用户选择交互模式、先选题或指定暂停点时遵从。

review.md 用主题 ID 对齐步骤产物即可，不额外生成七份流程文件。保存素材范围、版本和主要编辑决策，不输出内部逐步推理，也不记录未实际运行的状态。需要恢复时先读已有 review 与对应稿件，无法判断是哪个稿件则只问一个定位问题。
